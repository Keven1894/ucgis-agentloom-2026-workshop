AgentLoom × UCGIS — Reference Demos

Four heterogeneous data sources, four validators-green catalogs, four domain KG snapshots. Models are uncertain; the knowledge layer + validators are what converge everyone toward the same outcome.

Pick a dataset → explore foot-guns with the agent → externalize knowledge via propose-review → build a FAIR web catalog. These are the reference demo builds in demo/reference/ — compare your work against them; your fork still starts framework-only.

Why these four datasets?

Geospatial data does not arrive in one shape. We deliberately picked four heterogeneous sources so the same protocol — discover foot-guns → externalize knowledge → build a FAIR catalog — has to survive different geometries, encodings, and auth models. If the loop works across all four, it works for the source an attendee brings tomorrow.

Selection principles

  • Span the geometry spectrum — point events, point + time series, and polygons, so attendees meet both feature ingestion and basemap/join thinking.
  • Vary the failure modes — each source carries a different "foot-gun" (epoch-ms time, two-call joins, sentinel values, hyphenated ISO keys) that only surfaces when you actually read the data.
  • Mix auth and access — three keyless feeds plus one API-key source (OpenAQ), so the credential story gets rehearsed without blocking everyone.
  • Public, citable, FAIR-friendly — all are open, well-documented, and reusable, which makes them honest examples for a catalog about findability and reuse.
  • Vendored snapshots — each ships an offline snapshot so the workshop runs even when the network or a live API does not.
