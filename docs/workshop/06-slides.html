What you leave with

A validators-green catalog in your fork, domain KG nodes you proposed and accepted, and an open PR.

What you'll do today

1. Pick a dataset→ 2. Explore data & foot-guns with the agent→ 3. Externalize what you learn into the KG→ 4. Build a FAIR web catalog from it

One source (D1–D4). Interactively surface its quirks with Cline, turn each quirk into a proposed → accepted knowledge node, then let those nodes drive a catalog that passes the validators.

The model is non-deterministic — two people, two runs, different code. The knowledge layer + validators are what converge everyone to the same kind of outcome.

The promise — and where it breaks

"Describe the app → get working code."

Cline + GPT-5.2 can ship a Leaflet catalog today.

The gap isn't one task — it's session 2, a teammate, a new source, an audit 3 months later.

The real question

Not "can the agent do it once?" (yes).

"Where does the prompt come from, the 50th time, for the 10th person, with a traceable source?"

A prompt is one-shot. When the session ends, the reasoning is gone.

What a hand-written prompt cannot give

PropertyWhy "better prompt" can't fix it
PersistencePrompt dies with the session
Indexed retrievalDump-all → token blow-up + contradictions
ProvenanceNo audit trail, no human accept-gate
CompoundingMistakes don't become reusable nodes

+ portability across hosts · + team shared memory

What AgentLoom is

Not a better prompt — infrastructure that produces prompts reliably, at scale, with provenance, across sessions/people/hosts, and gets better over time.

KG → MCP kg_search (top-k) → propose → review → accept → validators

What we do NOT claim

  • ❌ Beats an expert's hand-tuned prompt on a single point
  • ❌ Agent never violates rules (runtime is probabilistic)
  • ❌ Deterministic end-to-end

✅ Durable properties on previous slide — verifiable on the dashboard today
